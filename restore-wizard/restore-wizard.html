Stocksite Restore Wizard

Detecting operating system…

This wizard runs on the Developer computer or the selected Windows/macOS restore target. The SERVER supplies only authenticated package downloads; the trusted local helper performs local work and never runs remote manifest commands. Database credentials belong in the helper's local environment, not in this page. Each consequential local restore action pauses for its own approval; approving one action does not approve the next.

Secret warning: the website archive may contain encrypted production `.env` configuration because an administrator authorized its inclusion. The helper will not decrypt or install it. Configure new environment-specific credentials locally; reusing production credentials can grant this computer production access.

Set up the local helper (Windows or macOS)
  1. Use supported 64-bit Windows 11 desktop build 26200 or newer (25H2+). Install x64 Node.js 22 or newer on an active/maintenance LTS line from nodejs.org, keeping npm enabled. Separately install PostgreSQL 18 or newer with its local server plus psql and pg_restore from the official PostgreSQL Windows download page. Do not use Windows 10, Windows Server, older Windows 11 builds, or ARM Node as a supported target. Review each installer and publisher yourself; the helper never downloads or launches installers, bypasses UAC, starts services, or requests elevation. Reopen PowerShell after installation and use Check this PC to recheck.
  2. Open Windows Services, start the PostgreSQL 18 service, then open pgAdmin and connect to this local server. Under Login/Group Roles → Create → Login/Group Role, create a login role named stocksite_local with a new local password. Under Databases → Create → Database, create a database also named stocksite_local and set its Owner to that role. If either name already exists, choose a new unused name for both. The helper later verifies that this role can connect, owns the selected database, and that the database is empty; it never creates, drops, or overwrites database objects.
  3. Download the unchanged source files stocksite.backup, website-code.zip, original-assets.zip, thumbnails.zip, restore-package-manifest.json, and checksums.sha256 into one private folder. Download and extract stocksite-restore-helper.zip separately to a user-owned folder. Keep the downloaded package originals unchanged.
  4. In File Explorer, open the extracted helper folder, click its address bar, type powershell, and press Enter. Run npm ci --ignore-scripts. Copy .env.example to .env without overwriting any existing file. To generate a random token without displaying it, run $b=New-Object byte[] 32; $r=[Security.Cryptography.RandomNumberGenerator]::Create(); $r.GetBytes($b); Set-Clipboard ([Convert]::ToBase64String($b)); $r.Dispose(); Write-Host 'Random token copied; paste it only into helper/.env.', then replace the example RESTORE_HELPER_TOKEN value in the private .env using Notepad and clear the clipboard with Set-Clipboard -Value ''. Never paste the token into a command, URL, or shared file. In File Explorer, right-click the helper folder and .env, choose Properties → Security, and ensure only your trusted Windows account can read them. The helper does not configure Windows ACLs.
  5. Run start-windows.cmd from that helper folder. Keep its terminal open. Open http://127.0.0.1:43127/ and enter the helper token. Under Local setup, enter the loopback host, PostgreSQL port, role name/password, matching empty database name, and free Stocksite port. Enter the independently trusted Ed25519 public key, unless already configured in helper/.env. The form keeps the database password in helper memory only and does not write it to helper/.env. Use Check this PC and resolve every required failed check before continuing.
  6. Do not use a file:// URL for helper API operations. The helper binds only to loopback, rejects remote database hosts, and generates a cryptographically secure local-only JWT secret if one was not explicitly configured.

Manifest links are informational. The helper will not silently install software or elevate privileges.

    Fresh PC readiness

    This read-only check inspects Windows version and architecture, Node.js/npm, PostgreSQL client tools, the configured loopback PostgreSQL connection and server version, the Windows PostgreSQL service, and the application port. pg_dump is reported for completeness but is not needed to restore a package. A client tool alone is not treated as a running database server. This check never installs software, starts services, creates roles/databases, or changes system settings.

      Local setup · PostgreSQL and trust

      Create the role and database first using pgAdmin on this PC: under Login/Group Roles, create a login role (suggested name stocksite_local) and give it a new local password. Under Databases, create a new database (suggested name stocksite_local) and set its Owner to that same role. Do not reuse an existing database or a website/production login. If these names already exist, choose new unique names. The helper verifies the configured role can connect, owns the selected empty database, and reaches PostgreSQL 18+ on loopback. It never creates, drops, or overwrites database objects.

      The signing public key is not a password, but it is a trust decision: obtain the base64 Ed25519 SPKI DER key through a trusted channel independent of the downloaded package. Never accept a key merely because it came inside the package.

      The password and public key are sent only to the authenticated loopback helper and kept in helper memory for this run; they are not written to helper/.env, returned in responses, logged, or stored in this browser. The helper creates a fresh local-only JWT secret automatically. To use a key already configured in helper/.env, leave the public-key field blank.

      Step 1 · Sources

      Enter the native Windows or macOS paths to the four verified package artifacts. Keep the database backup, package manifest, checksum file, and all three ZIP archives together. Browsers do not expose a selected file's native path to this local helper, so path entry is the supported fallback. The helper verifies package checksums and inventories before extracting the website, originals, and thumbnails into private staging folders. The database source must be a PostgreSQL custom-format .backup file.

      Step 2 · Destinations

      Select new, non-overlapping folders and an already-created, empty PostgreSQL database. The helper refuses existing destination folders and non-empty database targets. Source/schema compatibility is not established; normal Stocksite backend startup may run database initialization/migrations and requires lifecycle schema migrations 028–030 to be present. Use only a disposable local database.

      Enter full local folder paths (for example C:\Stocksite-Restore\site). Paths with spaces are supported; check the drive letter and each folder name carefully. The helper checks that each destination does not already exist, paths do not overlap, and there is enough free space before extraction. Role/database creation, service startup, Windows ACL review, and software installation remain manual steps; the helper reports specific next actions when a check fails.
