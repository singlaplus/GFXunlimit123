Stocksite Restore Wizard

This tool prepares a separate local Stocksite restore on a computer you choose. It does not automatically install software or overwrite your existing website.

The helper performs checks and approved restore actions on the computer where it is running. Each important action asks for separate approval. It never decrypts or installs production .env credentials.

Important: the website archive may contain encrypted production settings because an administrator approved including them. The helper does not decrypt or apply those settings. You must configure new local credentials. Reusing production credentials may connect this computer to production systems.

Step 1 · Choose the computer that will receive Stocksite

Checking this computer…

Choose the operating system of the computer where Stocksite will be restored. The computer used to download this page is only a hint; it does not choose the target for you.

Step 2 · Prepare the chosen computer and package files

What you need: the restore package files, a local helper folder, Node.js, and PostgreSQL. Why: the helper checks the files and guides the restore; it does not install system software or create your database.

Simple terms: Node.js is the program that runs the helper and website tools. PostgreSQL is the database software. A database is where Stocksite stores its records.

What the helper can do: check package signatures, checksums, paths, computer requirements, and database safety; then, only after your separate approvals, restore the database, extract to new folders, configure local settings, install the site's project dependencies, build the website, and start its backend. What you must do manually: install Node.js/PostgreSQL, start PostgreSQL, create the new role/database, protect the helper token, and review any operating-system permission prompts.

  1. On Windows, use supported 64-bit Windows 11 desktop build 26200 or newer (25H2+) and x64 Node.js 22+ on an active or maintenance LTS line. On macOS, install a currently supported Node.js LTS release for your Mac's processor. Get Node.js from nodejs.org.
  2. Install PostgreSQL 18 or newer on the chosen computer, including the local server and psql/pg_restore tools. Use the official PostgreSQL downloads. The helper does not install PostgreSQL, start its service, or create roles/databases.
  3. Keep stocksite.backup, website-code.zip, original-assets.zip, thumbnails.zip, restore-package-manifest.json, and checksums.sha256 together in a private folder. Extract stocksite-restore-helper.zip into a separate folder. Do not rename or edit package files.
  4. Open a terminal in the extracted helper folder and run npm ci --ignore-scripts. Copy .env.example to .env without overwriting an existing file. Replace the example RESTORE_HELPER_TOKEN with a new random value at least 32 characters long. Keep it private. The helper does not configure or verify Windows permissions.
  5. Start the helper with start-windows.cmd or ./start-macos.sh, whichever matches the chosen computer. Keep its terminal window open. Open http://127.0.0.1:43127/ in the browser on that same computer.

Next: check the computer, then create a new local login role and an empty database owned by that role. The helper verifies these are safe to use but does not create them.

Windows manual setup: use pgAdmin to create a new login role and a new empty database owned by that role; start PostgreSQL from Windows Services if needed. Review installer publishers yourself. The helper never requests elevation or changes Windows permissions.

macOS manual setup: use the PostgreSQL installer or package manager you trust to install and start a local PostgreSQL 18+ server, then use pgAdmin or psql to create a new login role and empty database owned by that role. The helper does not install or start services.

Next: enter the helper address and token, then use “Check this computer”.

Manifest links are informational. The helper will not silently install software or elevate privileges.

    Step 3 · Check the chosen computer

    You need Node.js, npm, PostgreSQL 18+, its command-line tools, a running local PostgreSQL server, and an available Stocksite port. This check explains missing or incompatible items. It only reads information; it never installs software, starts services, creates roles/databases, or changes settings.

      Next: follow the “Next action” shown for each missing or unsupported requirement. Once the checks are ready, verify the local database settings below.

      Step 4 · Connect to your new local database and verify package trust

      Required manual setup: before filling this in, create a new PostgreSQL login role with a new local password, then create a new empty database owned by that role. Do not select an existing Stocksite or production database. The helper checks the connection, database ownership and emptiness; it never creates, drops, or overwrites database objects.

      Trusted public key means a public verification key that you receive separately from this package through a trusted channel. It proves the package signer is the expected signer. Do not trust a key just because it is included in the downloaded files.

      The password and public key are sent only to the authenticated loopback helper and kept in helper memory for this run. They are not written to helper/.env, returned in responses, logged, or stored in this browser. The helper creates a fresh local-only application secret; it does not reuse production credentials.

      Technical details · connection and signature checks

      The helper accepts loopback PostgreSQL hosts only. It verifies PostgreSQL 18+, that the selected role owns the target database, and that the target contains no user objects. Package signatures use Ed25519. The independently trusted public key is encoded as SPKI DER in base64.

      Next: enter the four package file paths and check that the package files match their signed inventory.

      Step 5 · Find the four package files

      A local folder is a folder on the restore computer, such as C:\StocksitePackage or /Users/you/StocksitePackage. In File Explorer or Finder, locate the downloaded files and copy their full paths below. Keep all package files together and unchanged. The helper reads the manifest and checksum file from the same folder, then checks signatures, file checksums, and ZIP contents before using them. A checksum is a file fingerprint used to detect changes.

      Technical details · package verification

      The helper requires the separate restore-package-manifest.json and checksums.sha256 alongside these files. It checks the trusted Ed25519 signature, file sizes, SHA-256 values, safe ZIP paths, and the archive inventory. Missing, changed, or incompatible files are rejected; they are not silently skipped.

      Next: choose three new folders where the helper can create the restored site files.

      Step 6 · Choose new, empty destination folders

      The helper will create the folders you choose. Do not select an existing website, asset store, or folder with files you need. The three paths must not overlap. For safety, use a disposable local database and brand-new folders. Normal application startup may run local database initialization/migrations; full source/schema compatibility is not guaranteed.

      The helper checks that folders do not already exist, paths do not overlap, and enough disk space is available. If a check fails, read the message above and correct the named field; the helper does not overwrite existing folders.

      Next: review the preflight results and restore plan before authorizing any action.

      Step 7 · Preflight checklist and approval

      Before you continue, confirm each item. Validation must pass, and each later action will still ask for separate approval.

      • The selected target computer and helper platform match.
      • PostgreSQL is local, version 18 or newer, and the target database is new, empty, and owned by the role you entered.
      • The package files are unchanged and the independent signing public key is trusted.
      • The three destination folders are new, separate, and have enough free space.
      • You understand that the helper will not decrypt or install production environment credentials.
